## 本批实现

- 首轮 `TaskPlan.request_goals` 保留所有必要目标，包括无法执行的部分。首轮
  gap 引用与计划预算校验进入一次结构化修复；无效计划不能派发，生产链路记录
  固定 pipeline error，并保守合成，而不是执行非法计划。
- 正式 `build_support_runtime` 无条件注入 `ResponseGuard`。手工构造且不注入
  guard 的旧图测试只用于底层调度回归，不作为生产回答策略的验收。
- 独立最终评估输入原问题、已声明目标、原始 draft、实际证据/缺口、授权能力目录、
  会话上下文和实际调用状态。不得只评估 Planner 选择了执行的任务；必须保留已
  声明目标，也可以补入 Planner 遗漏的目标。覆盖和语义正确性仍依赖模型判断。
- 内部 `ResponseReview` 枚举技术阻碍类型，不是业务问题分类；每个目标声明支持
  状态、来源引用、解释或可信记录渲染、必要时的澄清资格。未知引用、漏目标、
  不完整/不一致评估、非法输出和超时均保守回退。
- 代码分别组合真实记录、知识说明和限制，不再用记录清单覆盖整份回答。资源编号、
  时间和可见性从适配器校验记录渲染，不接受模型伪造值。
- 单目标混合记录与非记录来源时拒绝，不允许替换知识正文后仍标 answered。
  未处理的实际工具错误即使伴随成功证据也必须保守 partial，并在正文说明调查
  尚未完成；已明确关闭的历史缺口不重复阻断。
- 有真实冲突而无法结构化定位时，整份进入来源摘录/冲突声明 fallback，不能一面
  保留肯定结论一面只改 partial 标签。fallback 不使用 Worker 或聚合器自由结论。
- 所有必要目标有支持、聚合证据门通过且无未处理执行失败才 answered；有可回答
  部分则 partial。无可回答部分且全部目标明确能力不可用、无技术失败才 unsupported。

## 澄清与故障边界

`missing_user_input` 必须绑定现有能力的实际必填 schema 字段、明确问题及其如何
使已有能力继续执行的理由。执行器从真实顶层 required 校验生成缺失字段证明；
Adapter/模型不能自报证明。已提供字段由实际调用记录，不传原始参数值，已知字段
不能被再次索取。Worker 将这些字段名和工具错误带入最终评估。

工具暂不可用、权限失败或不存在能力不能变成“补充 ID 即可查询”。原问题和历史
中的自然语言信息是否足够仍需模型判断；schema 缺失证明仅表示某次实际工具调用
参数缺失，不是对整段自然语言信息缺失的形式化证明。

draft 最多 18 秒，最终 review 最多 24 秒，按请求剩余预算留出最终响应时间。draft
失败或超时直接进入可信来源 fallback；review 失败也不丢弃已采证据。取消继续
传播，不吞掉客户端取消，不进行无限修复。通常每请求新增一次模型 review 调用。

首轮修正后 run `8e878c87` 四条 HTTP 均返回 200，但复合问题与 Workflow 故障
问题的最终 review 超过原 18 秒上限，进入 partial 摘录回退。复合问题严格验收未
通过，不把引用数量或来源摘录视作完整知识说明。随后限制评估输出长度、去除
聚合器自由结论的重复输入（完整工具证据仍保留），将 review 上限调整为 24 秒。
回退同时明确原请求仍未完成覆盖核查，不能被当作语义通过。

run `60c37118` 复合评估未超时，但旧 `explanation` 被模型理解成英文审核理由，
不是中文用户操作说明；故障问题还出现了来源未明确支持的查找前提描述。此轮
同样不计语义通过。协议改用 `answer_text`，明确是直接展示给用户的真实答案，
拒绝旧字段别名和中文问题的纯英文非记录答案；要求具体步骤/字段来自所引用
资料，能力目录不能被推断为整个产品没有其他 API。这些是窄防线，不能形式化
保证任意中文答案都准确或可操作，真实正文仍须人工核查。

## 剩余计划

四条真实 HTTP 问答不能证明所有复杂请求或所有声明都正确。新缺口闭环的真实
语义验证、真实下游故障注入、历史会话 UI、流式前端和服务器生产交付仍分别验收。
本批仅恢复已停止的共享依赖，未再次主动重启运行中的数据库或关闭共享 Gateway
与模型，也未删除旧测试数据。

下一批用户端功能优先为服务端会话历史恢复与知识来源详情展示；复杂问题的
更广泛语义样本、目标标题可读性与响应延迟继续专项回归。Workflow 实际失败节点
查询并不在当前只读能力中，不能靠用户补一个 ID 宣称已支持；如要提供该功能，
应另行开发授权的只读能力并验证权限、数据与证据协议。
