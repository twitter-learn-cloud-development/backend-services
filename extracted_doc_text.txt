1 项目背景与需求分析1.1 项目背景/* 写作提示：说明项目来源、应用场景以及希望解决的问题。重点回答：为什么要开发这个系统？谁会使用这个系统？目前存在什么问题？系统能够带来什么价值？请结合实际项目背景，描述该系统的来源、目标用户群体、当前存在的痛点问题以及预期能够带来的效益和价值。 */1.2 涉众分析/* 写作提示：识别项目相关人员及其关注点。例如：普通用户、管理员、运营人员、第三方机构等。说明不同角色的主要需求和职责，建议列出涉众清单表格，包含涉众名称、角色描述、主要职责、关注点和期望，并分析不同角色之间的利益关系和协作方式。 */1.3 功能需求分析/* 写作提示：从用户角度描述系统需要提供的功能。建议列出核心功能清单，描述主要业务流程，并给出用例图。重点回答：系统需要做什么？请将功能按模块或按用户角色进行分类，对每个功能进行简要描述，说明其输入、处理和输出。 */1.4 非功能需求分析/* 写作提示：分析系统质量要求。例如：性能要求（响应时间、并发用户数、吞吐量）、安全要求（身份认证、权限控制、数据加密）、可维护性要求（代码规范、文档完整）、可扩展性要求（模块化设计、接口开放）、可用性要求（界面友好、操作便捷）。重点回答：系统除了能用之外，还应该具备哪些质量特征？ */
2 系统分析2.1 用例模型/* 写作提示：建立系统功能视图。建议包含用例图和用例说明，每个用例应包含用例名称、参与者、前置条件、基本流程、备选流程和后置条件。重点回答：系统边界在哪里？用户与系统如何交互？请确保用例描述以用例文本为核心，尤其要包括主要场景和次要场景的叙述。 */2.2 领域模型/* 写作提示：识别业务领域中的核心对象及关系。建议列出系统中的实体、实体的属性以及实体之间的关联关系（一对一、一对多、多对多），并给出领域模型图（类图）。重点回答：系统中有哪些重要概念？这些概念之间是什么关系？请从业务领域的角度抽象出核心对象，不要过于偏向技术实现。 */2.3 关键业务流程分析/* 写作提示：选取最重要的业务场景进行分析。建议使用活动图、时序图或鲁棒图等任选适合的方式，展示业务是如何一步步完成的。请选择2-3个核心业务流程进行详细分析，说明参与者、系统对象之间的交互顺序和数据流转过程。 */2.4 分析结论/* 写作提示：总结分析阶段得到的重要结论。例如：系统边界、核心对象、核心业务流程等。说明这些分析成果如何支撑后续设计，即分析阶段的输出将作为设计阶段的输入，为架构设计、模块划分和数据库设计提供依据。 */

4 技术选型与工程决策4.1 技术选型/* 写作提示：列出项目采用的主要技术。例如：开发语言（Java/Python/JavaScript等）、开发框架（Spring Boot/Django/React等）、数据库（MySQL/PostgreSQL/MongoDB等）、开发工具（IDE、版本控制、构建工具等）。请说明每项技术在该项目中的用途和选择理由。 */4.2 方案比较与决策依据/* 写作提示：说明为什么采用当前方案。例如：为什么选择Spring Boot而不是其他框架？为什么选择MySQL而不是NoSQL数据库？是否考虑过其他方案？重点体现技术决策过程，建议列出候选方案比较表，从技术成熟度、社区生态、团队熟悉度、性能需求匹配度等维度进行比较分析。 */
5 系统实现5.1 项目结构/* 写作提示：展示项目目录结构。说明各目录职责和模块组织方式，建议以树形图或表格形式展示项目目录结构，并对每个重要目录或包的功能进行说明，体现项目的分层架构和代码组织规范。 */5.2 核心功能实现/* 写作提示：介绍主要功能实现过程。重点说明功能逻辑、关键类和核心流程，不要求大量贴代码。建议选择3-5个最具代表性的功能模块进行说明，描述其实现思路、涉及的主要类和它们之间的协作关系。 */5.3 关键代码分析/* 写作提示：选取具有代表性的代码进行说明。重点解释：为什么这样设计？体现了什么思想？建议选择2-3段关键代码（如核心算法、设计模式应用、复杂业务逻辑处理等），配合代码注释进行分析，说明其设计意图和实现原理。 */
6 AI辅助开发实践6.1 AI工具使用情况/* 写作提示：说明项目中使用过的AI工具。例如：ChatGPT、Cursor、Claude、Copilot、通义灵码等。请列出使用的工具名称、版本、主要用途和使用频率，并说明选择这些工具的原因。 */6.2 AI参与内容/* 写作提示：说明AI参与了哪些工作。例如：代码生成、文档生成、测试用例生成、SQL编写、Bug调试、需求分析辅助等。请具体描述AI在哪些环节提供了帮助，以及你是如何使用AI的（提示词策略、迭代优化过程等）。 */6.3 使用效果与反思/* 写作提示：分析AI带来的帮助和局限。例如：AI提高了哪些工作的效率？AI生成的内容存在哪些问题（如幻觉、过时知识、安全漏洞）？重点说明：哪些内容必须由开发者完成？请结合具体案例说明AI的适用场景和局限性，体现你对AI辅助开发的批判性思考。 */
7 系统测试7.1 测试环境/* 写作提示：说明测试所使用的软件与硬件环境。包括：操作系统版本、数据库版本、开发框架版本、浏览器版本（如果是Web应用）、测试工具版本、服务器配置（CPU、内存、硬盘）等信息。 */7.2 测试方案/* 写作提示：说明测试目标和测试策略。包括：测试范围（哪些功能需要测试）、测试类型（单元测试、集成测试、系统测试、性能测试等）、测试优先级、测试准入和准出标准。 */7.3 测试用例与结果/* 写作提示：列出典型测试用例。包括：正常情况（合法输入下的预期行为）、异常情况（非法输入或错误操作下的容错处理）、边界情况（临界值、极限条件）。建议使用表格形式，包含用例编号、测试项、前置条件、测试步骤、预期结果、实际结果和测试结论。 */7.4 问题分析与改进/* 写作提示：说明测试过程中发现的问题及修复过程。包括：Bug描述、严重程度、原因分析、修复方案、验证结果。建议对发现的问题进行分类统计（如功能缺陷、性能问题、界面问题等），并分析问题的根因。 */
8 项目管理与过程记录8.1 项目计划/* 写作提示：说明任务安排和时间规划。建议使用甘特图或任务分解表，展示项目的主要阶段（需求、设计、编码、测试、部署）、各阶段的起止时间、里程碑节点和任务分配情况。 */8.2 开发过程记录/* 写作提示：记录关键里程碑。例如：需求完成、设计完成、编码完成、测试完成、部署上线等。请按时间线记录项目的关键事件和决策点，反映项目的实际进展与计划的对比。 */8.3 风险与问题处理/* 写作提示：说明开发过程中遇到的问题以及解决方法。包括：技术难点（如框架选型、性能瓶颈、兼容性问题）、管理问题（如进度延误、需求变更、沟通障碍）和解决方案。请体现问题识别、分析和解决的过程。 */
9 总结与反思9.1 技术收获/* 写作提示：总结学习到的技术知识。例如：新掌握的编程语言特性、框架使用技巧、数据库优化方法、前端交互技术、设计模式应用等。请结合具体的技术点和项目实践进行说明。 */9.2 工程收获/* 写作提示：总结在需求分析、建模设计、项目组织等方面的收获。例如：如何与用户沟通获取需求、如何进行系统分析和设计、如何组织代码结构、如何进行团队协作等。请体现软件工程方法论在实际项目中的应用体会。 */9.3 不足与改进方向/* 写作提示：分析项目存在的问题以及未来改进思路。例如：功能不完善之处、技术债务、性能优化空间、架构演进方向等。请诚实地分析项目的局限性，并提出可行的改进计划。 */9.4 课程设计体会/* 写作提示：结合软件工程专业培养目标，总结本次课程设计的整体体会。重点思考：从"证明你写出了一个系统"到"证明你完成了一次工程化软件开发"的转变，体现你对软件工程本质的理解，以及在AI时代软件开发者应具备的核心能力。 */
